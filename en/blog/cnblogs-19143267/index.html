Perforce Stream Overview

What Is a Stream?

My understanding is that a Stream is Perforce’s smarter counterpart to a traditional branch. Its visual view makes synchronization relationships between branches easier to see.

Advantages and Disadvantages

  • Advantages: concurrent development without interfering with one another; fewer changes to the mainline; a clear hierarchy.
  • Disadvantages: history is somewhat harder to inspect; multiple workspaces are usually needed (you can switch between Streams in one workspace by changing its root directory, but this is less convenient).

Note: keeping a local folder for each Stream speeds up workspace switching and saves time.

Creating a Stream

Creating a Stream Depot (P4Admin)

  1. Open P4Admin.
  2. Choose File → New → Depot and select Stream as the type.
  3. Set Stream Depth (the depot’s hierarchy depth; 2 is recommended so the depot can contain multiple Streams).

Creating a Mainline

  1. Open P4V.
  2. Choose File → New → Stream.
  3. Set Stream Name.
  4. Select mainline for Type.

Note: check the save location (depot/path).

Creating a Branch

Method 1: File → New → Stream.

Method 2: right-click the parent node (such as the mainline) in StreamGraph or the Stream list to create it.

Branch Types
  • Development: for long-term projects and major new features. Suitable for versions that evolve over time.
  • Release: for bug fixes, testing, and release distribution.
    • Note: when creating a Release branch, I recommend disabling automatic propagation “From parent” to prevent mainline updates from automatically reaching the release version, while still allowing fixes to be merged from Release back to the mainline.
  • Virtual: narrows the scope and submits directly to the parent, often acting as a filter for a specific subset.
  • Task: a lightweight branch for short-term bug fixes and small features. It can reside in another Depot, and its parent can be empty or in another depot (including a standard depot).
    • I recommend keeping these in a Task Depot for centralized management later; check that Location points to the Task path and adjust it manually if necessary.
    • Note: a Task cannot be deleted after creation or share a name with another Task; it is invisible when unused.

Things to check when creating a branch:

  • “Automatically create a workspace” can be left unchecked, as needed.
  • “Populate the branch with files from the parent” is checked by default and usually should remain so.

Using Streams

Creating a Stream Workspace

  1. Create a Workspace.
  2. Set the Workspace name.
  3. Set the Workspace root.
  4. Select the corresponding Stream.

Switching Workspaces (StreamGraph)

  • Open StreamGraph from View in P4V.
  • Within the same Depot: drag the “computer” icon onto the target Stream to switch quickly; Perforce downloads or removes differing files automatically, while the workspace root stays the same.
  • Between different Depots: the usual approach is to switch workspaces. If you are constrained by a workspace limit (such as ≤10), you can switch by editing an existing workspace:
    1. Right-click the workspace in the Workspaces view → Edit.
    2. Change Workspace root to the target project directory.
    3. Change Stream to the target project’s Stream (it need not be the mainline; I recommend matching the local directory to make linking easier later).
    4. Choose whether to “copy” files: do not copy if the files already exist locally; otherwise, copy them.
    5. If you choose not to copy, run the sync command (see “Perforce Commands” below).

Merging and Updating

  • An upward arrow between two Streams means an update is available (copy to child/parent); a downward arrow means a merge is available.
  • No arrow: that direction is currently unsupported; gray arrow: already identical; green arrow: updates or differences exist.

Suggested workflow:

  1. Switch the workspace to the “target Stream” first. For example, to bring changes from a personal Stream into the mainline, switch to the mainline.
  2. Right-click the target Stream: Merge to merges, and Copy to copies updates.
  3. Select Source Stream (meaning “from there to here”).
  4. Enable automatic merge and submit; if there are conflicts, handle them manually before submitting.

Linking External Files (Similar to SVN Externals)

Purpose: use files from another depot (usually a shared depot) in the current depot.

Example: the Prefixed plugin

  • Plugin location in the shared depot: .../Save/UnrealPlugins/Prefixed/5.2/...
  • Right-click the mainline to edit it, and add the mapping under “Advanced.”
  • Click Apply.

Note: branches inherit the mainline settings automatically; if only one branch needs this, edit only that branch.

Perforce Commands

Viewing and Using the Command Line in P4V

Sync Command (Without Downloading Existing Files Again)

p4 sync -k
  • Purpose: associates local files with the depot’s “synced” records, avoiding repeated downloads.
  • Recommendation: after it succeeds, run “clean” to verify and clean up.
