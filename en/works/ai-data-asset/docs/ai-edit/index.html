Edit Asset Data with AI

First create the required DataAsset in UE and let the plugin generate its JSON, then tell the AI where the file is and what to change.

JSON File Location

JSON files are stored in the project’s Saved/AIDataAsset/ directory (configurable). Paths correspond directly to the Content Browser structure:

Asset path in UEJSON file path
/Game/DA_DemoSaved/AIDataAsset/Content/DA_Demo.json
/Game/Data/Characters/DA_WarriorSaved/AIDataAsset/Content/Data/Characters/DA_Warrior.json

What to Check After Editing

  • Keep the UE editor running with automatic synchronization enabled while editing JSON. Monitoring does not run while the editor is closed; edits made then are handled at the next startup under the startup rules in Synchronize DataAssets and JSON.
  • Create the UE asset first, then edit its JSON. Creating JSON alone does not create a DataAsset, and orphan JSON may be removed during startup cleanup.
  • Preserve the exported JSON structure, including the sample’s NativeClass field. It describes exported type information. Current import finds an existing asset by the JSON path rather than using this field to create one. Changing it cannot make the plugin generate a new asset type.
  • Invalid JSON or asset field-structure changes may cause import to fail. Check logs and actual asset contents after editing, and test in UE. Synchronization does not replace game-rule validation.

Common situations. If JSON is not updating, check that automatic synchronization is enabled, the editor is running, and the path corresponds to an existing asset. If asset values changed but a save warning appeared, check file write access and version-control checkout status before saving. JSON not regenerating immediately after deletion follows the deletion rules in the synchronization guide; it does not mean the UE asset was deleted.
