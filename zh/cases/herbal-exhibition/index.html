项目介绍

这是一个基于 UE 的中医药可视化展示项目，将药材三维模型、显微切片、药材功效和人体经脉放在同一套交互程序中。用户可以按类别查找药材，查看图文和语音介绍，切换模型与切片，也可以通过人体模型观察经脉走向和药材归经关系。

我负责展示程序的交互与数据组织，包括药材模型自适应、人体观察操作、经脉与穴位显示，以及图片、音频和模型的加载。同时，我用 Python 制作了外部数据编辑器，并编写 JSON 转 DataTable 的 UE 插件，让外部资料能够接入已有的数据查询与展示流程。

项目既要呈现现有素材，也要方便后续扩展。新增内容在已有分类和支持格式的范围内，由编辑器维护记录与资源，展示程序负责读取、检查和显示。药材知识、模型和图片等专业素材作为内容接入，我的工作集中在程序、交互功能与配套工具。

功能实现

药材检索与功效展示

我将药材资料按分类、名称、功效和产地等信息组织起来，提供对应的查询与筛选接口。用户可以先选择类别，再查找具体药材；关键词查询也可以匹配资料中配置的名称、标识和功效文本。

选中药材后，程序读取该条记录的介绍、缩略图、背景、语音和模型配置，再交给界面展示。功效摘要和完整介绍分别保存，列表可以显示简要信息，详情页再展开阅读，展示内容不需要全部写在界面逻辑里。

内置药材和通过外部编辑器补充的记录进入同一套浏览列表。展示端统一处理选择与内容切换，维护人员可以沿用已有分类增加资料。

药材模型切换与自适应

一味药材可以配置多个展示模型，模型的名称和数组顺序用于组织切换。例如全株、根部或其他形态可以作为不同条目接入，具体展示哪些模型由实际素材决定。

我为药材模型做了自适应展示，并为每个模型提供目标展示尺寸配置。不同模型原始大小不一，切换后按配置调整显示尺度，方便在同一展示场景中观察，也减少逐个手动设置展示大小的工作。

外部编辑器同样可以填写模型名称、选择模型文件和配置目标最长边尺寸。程序将这些配置带入展示流程，使外部新增模型也能使用已有的模型切换与尺寸适配逻辑。

资源异步加载与下一项预加载

模型、语音等主要展示资源采用异步加载。我将资料选择与资源准备分开，让文件读取、音频解码和模型加载通过异步任务完成，再将结果交给展示端。

用户查看当前药材时，程序会自动在后台准备下一味药材的模型和语音，并保留已加载的资源。顺序切换时优先使用提前准备好的内容，减少切换当下读取、解码和加载资源带来的等待与停顿，让连续浏览保持流畅。

内置资源通过 UE 的异步加载接口请求；外部模型采用后台文件处理和异步模型构建，外部语音在后台读取并解码，完成后再返回展示端使用。两种来源都纳入当前项与下一项的预加载管理，加载状态准备完成后再通知界面继续展示。

切换过程中使用请求标识区分新旧选择，取消已经失效的加载任务，避免上一味药材的加载结果回到当前界面。资源刷新后也会重新检查当前资料的加载状态，让显示内容对应更新后的记录和素材。

显微切片浏览

显微切片按药材标识关联，每条记录包含说明和不同倍率的图像。我负责切片数据读取、药材关联与倍率组织，让用户能从药材资料进入对应切片，查看同一药材的不同观察图像。

目前支持按配置组织 4×、10×、40× 图像，每个倍率下可以有多张图片。界面根据实际存在的图像生成可查看的倍率，不把缺少素材的倍率当作有效内容。

外部新增切片也通过相同接口提供给展示端。维护人员在编辑器中分别选择各倍率图像，程序读取后与已有切片资料一起组织，用户沿用原有浏览方式查看。

人体模型旋转与镜头缩放

我为人体展示加入了拖拽观察和相机缩放。用户在人体交互区域内水平拖拽，可以旋转组合后的人体模型，从不同方向查看；通过滚轮拉近或拉远镜头，观察整体结构或局部位置。

人体相关模型按标记组合后统一旋转，经脉、穴位等部件随人体保持对应。操作区域与界面交互分开处理，拖拽结束、交互区域失效或页面退出时会清理拖拽状态，并提供人体朝向复位。

相机缩放可以配置移动幅度与距离范围，支持沿当前视线或鼠标命中位置拉近观察，也提供恢复初始镜头位置的接口。实现中保留靠近目标的距离限制，避免镜头持续推进到模型内部。

经脉、穴位与药材归经

经脉展示既支持按单条经脉查看，也支持从药材的归经资料进入关联经脉。一味药材可以关联多条经脉，程序读取对应配置后，一起控制相关经脉和穴位的显示。

我通过场景模型的标记管理人体、脏器、经脉与穴位，提供显示和筛选接口。选择经脉后，场景保留当前相关的经脉与穴位；也可以恢复全部显示，或单独调整脏器显隐，便于观察空间位置。

穴位名称由配置与场景标记关联，支持显示开关和名称筛选。文字位置跟随对应模型，并根据相机距离调整显示大小，兼顾整体观察与局部查看。

经脉走向通过配置的序列动画展示。我负责按当前选择组织播放、停止和完成通知；选择药材归经时，可以加载关联经脉的展示动画，使药材介绍与人体上的经脉表现对应起来。

Python 外部数据编辑器

我用 Python 制作了独立于 UE 展示程序的外部数据编辑器，主要维护药材和显微切片对应的 JSON 记录。维护人员通过列表选择记录，在表单中填写资料、选择素材并保存，由工具处理数据文件的读写。

药材记录可以维护名称、介绍、分类、产地、缩略图、语音和多个模型配置；模型条目还可以设置展示名称与目标尺寸。切片记录则维护说明，以及各倍率对应的图像。工具同时提供记录新增、编辑、改名、分类调整和删除等操作。

图片、音频和模型通过文件选择接入，工具将记录与素材放入约定的数据目录。资料和媒体之间的对应关系由工具维护，避免每次扩展都要进入 UE 工程重新配置全部内容。

编辑器会显示缺失资料、资源异常等检查结果，也可以读取展示程序产生的验证报告，将引擎侧发现的问题对应到具体记录和字段。维护人员可以按提示修正，再保存并重新检查。

JSON 转 DataTable 插件

我编写了配套的 UE 插件，将外部 JSON 记录转换为程序运行时使用的 DataTable。Python 编辑器负责维护资料，插件负责把资料转换为 UE 可以读取的数据结构，展示端继续沿用已有的查询和交互逻辑。

在这个项目中，每条外部 JSON 记录对应一行数据，文件名用于确定行标识。插件根据配置的目录和数据表模板读取记录，检查标识与字段结构，生成运行时数据表，并返回无法转换的记录和问题说明。

药材和切片模块从转换后的数据表中获取记录，再验证对应的图片、音频与模型。通过这一步转换，外部维护的内容可以进入原有程序的数据流程，界面不需要为外部 JSON 另写一套展示方式。

外部资料与内置数据合并展示

我将外部资料接入程序已有的数据查询和展示流程。程序启动后，由转换插件读取 JSON 并生成运行时数据表；药材模块取得记录，完成素材检查，再将有效外部药材加入对应分类，重建统一的浏览与检索列表。

合并过程保留内置资料资产，外部内容写入运行时使用的副本。界面通过统一接口获取记录，加载时再根据来源分别读取程序内资源或外部文件。外部新增的药材因此可以与内置药材一起被选择和展示。

这套扩展目前围绕药材与显微切片资料展开。维护人员在编辑器中完成记录和素材更新后，重新启动展示程序即可读取新内容；新增支持范围内的资料不必重新打包整个程序。

难点：让外部记录和素材真正进入展示流程

外部导入需要同时处理记录格式、素材文件和展示端的加载方式。数据文件能读出来，只说明记录可以解析；模型、图片和音频还要能够被程序实际加载，才能作为可用内容进入展示。

我先约定每条 JSON 记录的标识、分类和素材关联方式，在编辑器中检查外部记录是否重名、路径是否有效、必填信息是否齐全，并验证模型尺寸等数值。转换插件继续检查记录能否按数据表结构读取，展示端再排除与内置资料标识冲突的药材记录。这些检查帮助维护人员定位具体的数据问题。

素材检查分两步完成。编辑器检查图片能否解码、音频文件头与格式是否相符，以及模型文件的基本结构；展示端再尝试实际读取图片、音频和模型。未通过验证的药材记录不会进入合并后的展示列表，并将问题写入报告，供编辑器读取和提示修正。

内置模型与外部模型的加载方式不同，我通过统一的资料接口衔接两种来源。外部模型和音频先登记到加载模块，再由展示逻辑按记录取用；新增资料可以继续使用原有界面和切换流程，内置内容也保持原样。

保存端还要处理记录与素材的同步变化。我加入保存前的内容变更检查，发现其他操作已经修改资料时停止覆盖；数据记录先写入临时文件，写完后再替换原文件。替换或删除后不再被引用的受管素材会先移入回收目录，减少维护过程中的误删损失。

内容扩展与维护

  1. 在外部编辑器中新增或选择药材、切片记录，填写资料并确定分类。
  2. 为药材选择图片、音频和模型，配置模型名称与展示尺寸；为切片选择对应倍率的图像。
  3. 保存资料，根据检查结果修正缺失内容、文件格式或素材关联问题。
  4. 重新启动展示程序，在原有列表中查看新增资料，并检查模型、语音和切片是否正常显示。
  5. 如展示程序报告资源加载问题，在编辑器中定位记录、修正素材，再重新验证。

外部导入支持 PNG、JPG、JPEG 图片，OGG、WAV、MP3 音频，以及自包含的 glTF 2.0 GLB 模型。GLB 的模型、材质与贴图需要保存在同一个文件中。切片图像按实际提供的倍率配置。
