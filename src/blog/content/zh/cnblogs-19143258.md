# 如何设置TypeMap

## 补充：团队何时保留 Binaries
需要让不安装编译工具链的成员打开项目时，可以分发与明确源码提交、引擎版本、目标平台和配置一致的编辑器二进制。不要因为目录名叫 Binaries 就全部纳管，也不要把每台机器产生的临时构建结果都提交。

`+w` 让工作区文件保持可写，适合特定本机构建产物，但不代表签出、锁定或变更已提交。并发协作仍要制定谁生成并更新 DLL 和 `.modules` 的约定。引擎、源码和二进制不匹配时，本地可写也不能解决加载失败。

已有受管文件的类型不会仅因修改 typemap 自动更新，需在获授权的 changelist 中逐项核对。不要为本篇教程直接修改服务器 typemap 或批量改类型。忽略规则需由 `p4 ignores -v` 在自己的测试环境核对，不能把 Git 忽略文件整段当作已验证的 P4 规则；ignore 也不移除已受管文件。

可验证例：在独立测试工作区检查一份 DLL 与 `.modules` 的实际 filetype、同步后可写属性及打开记录，再让干净项目加载这一组产物。本文没有连接 P4 或重新验证现有 typemap，补充的是协作边界，非服务器操作结果。
