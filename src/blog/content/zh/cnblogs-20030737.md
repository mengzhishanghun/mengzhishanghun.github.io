UE：如何解决蓝图继承中子类修改组件属性影响父类的      问题
===

> © [mengzhishanghun](https://github.com/mengzhishanghun) · 原创文章\
> &#x20;首发于 [博客园](https://www.cnblogs.com/mengzhishanghun) · 禁止未经授权转载

***

## 前言

如果你在 UE 里用蓝图继承做过复杂项目，大概率碰到过这个怪现象：

- **父蓝图里该组件的「剪切 / 删除」菜单被灰掉了** —— 明明是父类自己的组件，却删不掉
- **子蓝图里修改该组件的任意属性（哪怕只是勾个 bool），改动会同步写回父蓝图** —— 子类的修改不再被隔离，上下游互相污染

如果中招过，大概率懂这种绝望。排查半天没头绪，网上搜到的方案千奇百怪（重建蓝图、改父类、删组件重加……），很多方案还会让继承链其他地方一起崩。

**SimpleBPInheritFix 就是专治这一种 bug 的插件**。右键任意受影响的蓝图一键修复，沿整条继承链自动扫描、签出、修复所有受损组件。不动其他字段，改动极保守。

***

## 一、这个 Bug 到底是什么

### 1.1 根本原因

UE 的 `UActorComponent` 有一个字段 `CreationMethod`，描述这个组件的"创建方式"：

| 枚举值                        | 含义                                       |
| -------------------------- | ---------------------------------------- |
| `Native`                   | 在 C++ 构造函数里创建的组件                         |
| `SimpleConstructionScript` | 通过蓝图编辑器的 Components 面板添加的组件（**正常的蓝图组件**） |
| `UserConstructionScript`   | 在 ConstructionScript 节点里动态创建的            |
| `Instance`                 | 运行时添加到具体 Actor 实例上的组件（**不应该出现在蓝图模板里**）   |

**Bug 的本质**：某些未知操作会让蓝图的组件模板（`ComponentTemplate`）的 `CreationMethod` 被错误设为 `Instance`。一旦变成 `Instance`，UE 编辑器就认为它不是"蓝图自己定义的组件"，于是：

- 父蓝图里的 Cut / Delete 菜单项走不同分支而被灰
- 子类的属性修改被当作"实例级修改"写回父模板（而不是在子类里产生 override）

### 1.2 为什么会触发

UE 编辑器内部的某些操作序列（比如特定顺序的蓝图复制、重命名、父类切换）会意外触发。具体复现路径难以稳定复现，但**一旦发生就持续存在**，保存后也不会自愈。

### 1.3 手动修复的麻烦

理论上只要把 `CreationMethod` 改回 `SimpleConstructionScript` 就好，但实际操作会遇到几个坑：

1. **组件可能同时出现在 SCS 节点和 ICH 记录里**（详见下文第三节），两个位置都要改
2. **继承链上多层蓝图可能同时中招**，只改一个没用
3. **子类蓝图**（用当前蓝图做父类的那些）也可能被污染，需要一起修
4. **源码控制下的文件默认只读**，需要逐个签出

手动靠点属性面板根本改不到这个字段。只能写脚本，还得对 UE 蓝图内部结构足够熟。

***

## 二、插件核心功能

### 2.1 一键触发

在 Content Browser 里右键任意 **Actor 蓝图**，选 **Component Repair → Fix Inheritance Pollution** 即可。

锚点选哪个蓝图不重要 —— 不管是父类、自身还是子类，插件都会沿整条继承链扫到底。

### 2.2 整链扫描

插件通过两个机制扫描整条继承链：

- **向上**：从锚点蓝图的 `ParentClass` 一层一层走到顶，收集所有作为父类的蓝图
- **向下**：用 UE 的 `AssetRegistry.GetDerivedClassNames()` 拿到所有派生的蓝图类

这两个集合合并去重后，就是本次需要检查和修复的完整范围。

### 2.3 SCS + ICH 双路径覆盖

蓝图的继承组件信息存在两个位置，必须都查：

- **SCS 节点**（`SimpleConstructionScript.AllNodes`）：蓝图直接定义的组件
- **ICH 记录**（`InheritableComponentHandler.CreateRecordIterator()`）：子蓝图对继承自父类的组件所做的 override 记录

插件对每个蓝图同时扫描这两处，任何 `CreationMethod == Instance` 的记录都会被发现并修复。

### 2.4 自动源码控制集成

修改前自动通过 UE 的 `ISourceControlModule` 把受影响的 `.uasset` 文件 CheckOut：

- **Perforce**：`p4 edit`
- **Git LFS**：请求 LFS lock
- **SVN**：`svn lock`
- **Git（无 LFS）**：基本无操作，文件本就可写
- **无源码控制**：整个签出阶段跳过

***

## 三、修复流程（5 阶段）

插件执行时按 5 个阶段推进，每个阶段在 Output Log 的 `LogSBIF` 频道都有清晰标记，方便排查：

| 阶段                      | 动作                                                             |
| ----------------------- | -------------------------------------------------------------- |
| 1. **GatherChain**      | 收集继承链（父类 + 自身 + 子类）                                            |
| 2. **ScanChain**        | 扫描每个蓝图的 SCS + ICH，找出所有 `CreationMethod=Instance` 的记录           |
| 3. **CheckOutFindings** | 通过源码控制签出涉及的 uasset                                             |
| 4. **ApplyFindings**    | 将 `CreationMethod` 从 `Instance` 翻转为 `SimpleConstructionScript` |
| 5. **MarkDirty**        | 将改动过的蓝图标记为脏，提示用户手动保存                                           |

如果扫描阶段没有发现任何受损节点（阶段 2 输出 0），插件会直接退出并告知"无需修复" —— **不会动任何文件**。

***

## 四、使用步骤

1. 安装插件，编译通过
2. Content Browser 里右键任意受影响的 Actor 蓝图
3. 选择 **Component Repair → Fix Inheritance Pollution**
4. 打开 Output Log，过滤 `LogSBIF`，查看执行情况
5. 编辑器弹出保存对话框，**保存被标脏的蓝图** 即完成

完整日志大致长这样：

```

[SBIF] ==============================================
```

## 五、常见问题

### 扫描结果 0 条但确有污染？

大概率不是本插件覆盖的问题（罕见情况）。完整复制 `LogSBIF` 日志到 Fab 产品页评论区协助排查。

### CheckOut 失败怎么办？

插件仍会完成内存修复，但保存前需要手动处理签出。常见原因：

- 文件被他人锁定
- 源控制服务器不通
- Workspace mapping 不包含该文件

先手动解决签出，再回 UE 保存。

### 会不会把正常组件改坏？

不会。插件的修复逻辑是：**只翻转 `CreationMethod` 这一个字段**（`Instance → SimpleConstructionScript`），其他任何属性都不动。这个字段对于蓝图组件模板来说本就不应该是 `Instance`，翻转回去只是恢复正确状态。

### 锚点蓝图选错会有影响吗？

不会。不管你右键的是父类、自身还是子类，插件都会向上向下扫描整条链，效果完全一致。

### 非 Perforce 能用吗？

- **Git**：签出基本是空操作，文件本就可写
- **Git LFS**：会自动请求 LFS lock
- **SVN**：执行 `svn lock`
- **无源码控制**：签出阶段整个跳过，直接进入修复

***

## 六、限制

- 只处理本插件覆盖的那种组件异常（`CreationMethod=Instance` 污染），其他类型的蓝图问题不在范围内
- Construction Script 里动态生成的组件不在扫描范围（那些本就不走 SCS/ICH）
- 仅支持 Actor 蓝图（非 Actor 的蓝图不存在此问题）

***

## 七、获取方式

Fab 搜索 **SimpleBPInheritFix** 即可获取。

- 支持：UE 5.2+
- 平台：Windows / macOS / Linux
- 编辑器专用插件，不影响游戏运行时
