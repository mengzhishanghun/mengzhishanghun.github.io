## 补充：Windows 头文件冲突
UE5 的 Windows 第三方库可能间接包含 Windows SDK 头文件，使宏或平台类型泄漏到后续 UE 头文件。排查时先看最早的错误及 include 链，不能把一串 `_Interlocked*` 错误都视为独立根因。

在 Windows 专属实现文件中隔离第三方 include，按当前引擎提供的平台包装头组织。原记录使用以下片段；这是 include 布局示例，未在本轮编译：

```cpp
#if PLATFORM_WINDOWS
#include "Windows/AllowWindowsPlatformTypes.h"
#include <winsock2.h>
#include <ws2tcpip.h>
// 在此包含需要 Windows 类型的第三方头文件。
#include "Windows/HideWindowsPlatformTypes.h"
#endif
```

Winsock2 通常应早于可能引入旧 winsock.h 的 windows.h。也要检查当前 UE 版本是否要求 WindowsHWrapper 或额外宏包装；不要凭这段代码替换整个项目的包含顺序。包装不解决 ABI、导入库、运行时依赖缺失或 DLL 搜索路径问题。

可在临时模块分别编译一个最小 include 示例和真实第三方头，定位是哪次引入污染；再验证模块链接及加载。原笔记含 UE 5.5 报错，不证明其他版本已通过。本补充删除私人路径和原始批量编译日志，不新增插件产品介绍。
