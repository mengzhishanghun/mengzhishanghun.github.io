# Blueprint generic struct serialization: memory layout versus persistence

## Problem and environment
Network communication, persistence and interaction with external programs are common needs and often involve converting data to byte arrays. CustomThunk can expose a Blueprint struct's real reflected type and address to a generic conversion function. Obtaining the address does not make a raw memory copy a valid save format for arbitrary structs. This article corrects UE5 serialization boundaries without presenting a particular plugin API.

## CustomThunk reads arguments
`CustomThunk` together with `CustomStructureParam` can implement generic struct parameters. `CustomStructureParam` identifies a generic struct parameter. The declared int32 is a reflection placeholder, not an instruction to cast a struct to an integer. A thunk consumes VM parameters in declaration order, checks the `FStructProperty` and address, then converts after argument reading is complete. Do not use `CastFieldChecked` before validation expecting a null result on failure. Declaration, VM order and output direction must agree. The fragment below is a parsing core, not a compiled complete thunk.

## Raw memory is not a persistence protocol
FString, TArray and object references contain dynamic storage or addresses. Whole-struct memcpy cannot restore them across processes and can corrupt lifetimes or cause double frees. Even integer memory representations need explicit byte order, width and protocol rules. Persistence requires a defined format, schema version, fields, encoding and validation. Reflected JSON handles supported field types; it does not automatically solve every object reference or compatibility problem.

## Actually parse the input JSON
```cpp
TSharedPtr<FJsonObject> Parsed;
const auto Reader = TJsonReaderFactory<>::Create(InputJson);
if (!FJsonSerializer::Deserialize(Reader, Parsed) || !Parsed.IsValid())
{
    return false;
}
FStructOnScope Temporary(StructType);
if (!FJsonObjectConverter::JsonObjectToUStruct(
        Parsed.ToSharedRef(), StructType, Temporary.GetStructMemory(), 0, 0))
{
    return false;
}
// Validate required fields and business values before copying.
StructType->CopyScriptStruct(Destination, Temporary.GetStructMemory());
```

Validate StructType and Destination first. The destination must be initialized and type-compatible. Serializing an empty JsonObject before conversion does not read InputJson. `{}` is a valid JSON object, but acceptance depends on required-field rules; it is neither automatically invalid nor proof of complete valid fields.

## Try it and understand the limits
Round-trip a struct containing FString and TArray through JSON and compare fields. Malformed JSON or missing required fields should preserve the destination. Version the format and test unknown fields and numeric ranges. Assess floating-point output against actual values and acceptable error instead of claiming every conversion loses severe precision. No UE compilation, execution or cross-version testing was performed for this article.
