# Creation

![](/media-occurrence/blog%3Acnblogs-19165500%3Amedia%3A1)\
&#x20;Create a class derived from UDeveloperSettings\
&#x20;In the class specifiers, Config=Game means configuration in Game.ini; adding DefaultConfig makes it DefaultGame.ini\
&#x20;The name following config= is the configuration file name\
&#x20;So here the configuration is in DefaultVehicle.ini

# ini Configuration Format

![](/media-occurrence/blog%3Acnblogs-19165500%3Amedia%3A2)\
&#x20;The configuration format is \[/script/ModuleName/ClassName]\
&#x20;![](/media-occurrence/blog%3Acnblogs-19165500%3Amedia%3A3)\
&#x20;The Map format is ((key,value),(key,value))\
&#x20;Both Map and Array can be continued on subsequent lines using +, rather than writing everything on one line

# Editor Project Settings

![](/media-occurrence/blog%3Acnblogs-19165500%3Amedia%3A4)\
&#x20;The value following DisplayName= is the name shown in the editor's Project Settings

Categories are determined by the value following config=\
&#x20;It can be game, engine, or plugins\
&#x20;You can also use a custom value, which defaults to the engine category

After adding DefaultConfig, changing values here automatically generates the configuration file

# Access

![](/media-occurrence/blog%3Acnblogs-19165500%3Amedia%3A5)\
&#x20;Access it through GetDefault in C++\
&#x20;![](/media-occurrence/blog%3Acnblogs-19165500%3Amedia%3A6)\
&#x20;In Blueprints, call GetClassDefaults to access it

# Packaging Exclusions

![](/media-occurrence/blog%3Acnblogs-19165500%3Amedia%3A7)\
&#x20;First add the configuration files to exclude in DefaultGame.ini\
&#x20;![](/media-occurrence/blog%3Acnblogs-19165500%3Amedia%3A8)\
&#x20;Then add the reference declaration in the corresponding module, so packaging automatically copies the file into the packaged config directory\
&#x20;The benefit is that you can still change game rules by editing the configuration file after packaging
