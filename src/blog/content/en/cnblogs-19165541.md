UE: Implementing SSH Tunnels to Access Remote Services Securely
===

## Introduction

During UE project development, we often need to access databases, APIs, or internal services on remote servers. Exposing these services directly to the public internet poses security risks. An SSH tunnel provides a secure solution: it forwards a local port to a remote service through an encrypted SSH channel, keeping data transmission secure while avoiding direct exposure of the service.

This article explains how SSH tunnels work and how to implement this functionality in UE.

***

## Ways to Implement an SSH Tunnel

### Calling the System SSH Client

Let's start with the simplest approach: using the system's built-in SSH client:

**Windows (using the OpenSSH client):**

```cpp
#include "GenericPlatform/GenericPlatformProcess.h"

void CreateSSHTunnelByCommand(
    const FString& SSHHost,
    int32 SSHPort,
    const FString& Username,
    const FString& Password,
    int32 LocalPort,
    const FString& RemoteHost,
    int32 RemotePort)
{
    // 构建SSH命令
    // ssh -L LocalPort:RemoteHost:RemotePort Username@SSHHost -p SSHPort
    FString Command = FString::Printf(TEXT("ssh -L %d:%s:%d %s@%s -p %d -N"),
        LocalPort, *RemoteHost, RemotePort,
        *Username, *SSHHost, SSHPort);

    // 使用UE的进程管理启动SSH
    FProcHandle ProcHandle = FPlatformProcess::CreateProc(
        TEXT("C:/Windows/System32/OpenSSH/ssh.exe"),
        *Command,
        true,   // bLaunchDetached
        false,  // bLaunchHidden
        false,  // bLaunchReallyHidden
        nullptr,
        0,
        nullptr,
        nullptr
    );

    // 保存进程句柄用于后续关闭
    if (ProcHandle.IsValid())
    {
        UE_LOG(LogTemp, Log, TEXT("SSH隧道已启动"));
    }
}

// 关闭SSH隧道
void CloseSSHTunnel(FProcHandle& ProcHandle)
{
    if (ProcHandle.IsValid())
    {
        FPlatformProcess::TerminateProc(ProcHandle);
        FPlatformProcess::CloseProc(ProcHandle);
    }
}

```

**Pros and cons of this approach:**

✅ **Pros:**

- Simple to implement in just a few lines of code
- No need to integrate third-party libraries
- Uses the system's built-in SSH client

❌ **Cons:**

- Depends on the system environment (an SSH client must be preinstalled)
- Cannot enter a password through code (requires key configuration or manual input)
- Complex process management makes connection status difficult to obtain
- Poor cross-platform compatibility (different paths on Windows/Linux/Mac)
- Cannot retrieve detailed error information
- Unsuitable for packaged distribution (users' environments are beyond your control)

***

### Integrating an SSH Library

A more reliable approach is to integrate a dedicated SSH library.

Here we use the open-source combination of libssh2 + OpenSSL, which requires two key libraries:

**libssh2** — SSH protocol implementation

- Establishes SSH connections
- User authentication (password/key)
- Port forwarding
- 🔗 Source: <https://github.com/libssh2/libssh2>
- 📄 License: BSD 3-Clause

**OpenSSL** — Encryption support

- Provides underlying cryptographic algorithms
- Key exchange
- Data encryption/decryption
- 🔗 Source: <https://github.com/openssl/openssl>
- 📄 License: Apache 2.0

### How to Use These Two Libraries

Basic steps for integrating libssh2 into a UE project:

**1. Compile the libraries**

First, compile static libraries for libssh2 and OpenSSL for your target platform:

```bash
# Windows平台需要编译出
libssh2.lib / libssh2.dll
libcrypto.lib / libcrypto.dll
libssl.lib / libssl.dll

```

**2. Add dependencies in .Build.cs**

```csharp
// 添加头文件路径
PublicIncludePaths.Add(Path.Combine(ThirdPartyPath, "libssh2", "include"));
PublicIncludePaths.Add(Path.Combine(ThirdPartyPath, "openssl", "include"));

// 链接静态库
PublicAdditionalLibraries.Add(Path.Combine(ThirdPartyPath, "libssh2", "lib", "libssh2.lib"));
PublicAdditionalLibraries.Add(Path.Combine(ThirdPartyPath, "openssl", "lib", "libcrypto.lib"));
PublicAdditionalLibraries.Add(Path.Combine(ThirdPartyPath, "openssl", "lib", "libssl.lib"));

// 运行时需要的DLL
RuntimeDependencies.Add("$(BinaryOutputDir)/libssh2.dll", Path.Combine(ThirdPartyPath, "libssh2", "bin", "libssh2.dll"));

```

**3. Basic libssh2 workflow**

```cpp
#include "libssh2.h"

// 初始化libssh2
libssh2_init(0);

// 创建会话
LIBSSH2_SESSION* session = libssh2_session_init();

// 连接到SSH服务器（基于已有的Socket）
libssh2_session_handshake(session, socket);

// 用户认证
libssh2_userauth_password(session, username, password);

// 创建端口转发通道
LIBSSH2_CHANNEL* channel = libssh2_channel_direct_tcpip(
    session,
    remote_host,  // 远程目标地址
    remote_port   // 远程目标端口
);

// 后续进行数据转发...

// 清理资源
libssh2_channel_free(channel);
libssh2_session_disconnect(session, "Normal Shutdown");
libssh2_session_free(session);
libssh2_exit();

```

**Key points:**

- libssh2 needs to work with sockets; in UE, you can use `FSocket`
- Port forwarding requires a local listening socket to accept connections
- Data forwarding needs to run in a loop on a separate thread to avoid blocking the main thread
- All libssh2 operations require proper error handling and resource cleanup

### Comparing the Two Approaches

| Feature | Calling system SSH | Integrating an SSH library |
| -------- | ---------- | ------ |
| **Implementation difficulty** | Simple | Complex |
| **Environment dependencies** | Requires a system SSH client | None |
| **Password authentication** | Unsupported (requires manual input) | Fully supported |
| **Status monitoring** | Difficult | Fully supported |
| **Error handling** | Details unavailable | Detailed error information |
| **Cross-platform** | Inconsistent paths | Unified interface |
| **Packaged distribution** | Unreliable | Reliable |
| **Use cases** | Development and testing | Production environments |

**Conclusion:**

- If you only need a temporary test, calling system SSH is the quickest approach
- If you want a production-grade feature, integrating an SSH library is the only choice
