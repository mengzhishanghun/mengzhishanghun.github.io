# Common Client Operations

# Basics

The basics are operations that everyone using Perforce should know.

## Creating a Workspace

![](/media-occurrence/blog%3Acnblogs-19143256%3Amedia%3A1)

Set the workspace name and root directory, then choose the content mapped into the workspace.

√ means include.

\- means exclude.

X means clear.

Try these options yourself. This lets you control which files enter your workspace and reduce unnecessary updates.

## Submitting

Select the changelist to submit in Pending.

![](/media-occurrence/blog%3Acnblogs-19143256%3Amedia%3A2)

Right-click and choose Submit.

## Updating

Select the file or folder to update, then click GetLatest or right-click and choose GetLatestRevision.

![](/media-occurrence/blog%3Acnblogs-19143256%3Amedia%3A3)

## Viewing History

![](/media-occurrence/blog%3Acnblogs-19143256%3Amedia%3A4)

Left-click a file or folder to see its submission history.

1. Submission history.

2. Submission details, including time, author, and comments.

3. Files changed in this submission.

## Adding New Files

![](/media-occurrence/blog%3Acnblogs-19143256%3Amedia%3A5)

Right-clicking Mark for Add adds the selected files that are not excluded by ignore rules to a changelist.

## Deleting Files

![](/media-occurrence/blog%3Acnblogs-19143256%3Amedia%3A6)

Right-click Mark for Delete to delete the selected files.

They are first placed in a changelist; submit after checking that everything is correct.

## Checking Out Files

Most files managed by p4 are read-only and must be checked out before you can write to them.

Right-click CheckOut to check them out. By default, they go into the default changelist.

![](/media-occurrence/blog%3Acnblogs-19143256%3Amedia%3A7)

If you checked out many files but changed only some, should you submit the rest too?

No. Submitting unchanged files serves no purpose, clutters the depot, and makes submission history harder to read.

The correct approach is to revert unchanged checkouts as follows.

![](/media-occurrence/blog%3Acnblogs-19143256%3Amedia%3A8)

Select the changelist, right-click, and choose RevertUnchangedFiles.

## Reverting Files

Reverting is generally used when local content differs from the depot, or when an accidental checkout or edit needs to be restored to the depot version.

![](/media-occurrence/blog%3Acnblogs-19143256%3Amedia%3A9)

Select the files to revert in the changelist.

If a file is marked for addition, the addition is canceled and the local file remains.

If a file is marked for deletion, the deletion is canceled and the local file is downloaded again automatically.

If a file already exists in the depot and differs from the depot version, it is overwritten with the depot file; its checked-out state is also canceled, if applicable.

## Comparing Files

File comparison is often used to find and fix differences after a branch merge goes wrong.

You can also use it to see how a local file differs from the depot version. If there is no difference, it reports that the comparison failed.

Select a file and right-click to compare.

![](/media-occurrence/blog%3Acnblogs-19143256%3Amedia%3A10)

## Cleaning Files

Cleaning is generally used to restore the entire local workspace to the depot version.

It lists all local files that differ from the depot, including files outside version control, and lets you clean them all or keep them.

Note that cleaning does not clean files in changelists.

Procedure:

Select files, right-click, and choose Clean.

![](/media-occurrence/blog%3Acnblogs-19143256%3Amedia%3A11)

# Advanced Operations

For advanced operations, do not proceed unless you are confident about what you are doing.

## Undoing Submissions

### Undoing One Submission

![](/media-occurrence/blog%3Acnblogs-19143256%3Amedia%3A12)

Select a submission in history, right-click, and choose Undo.

### Undoing All Submissions After a Point

Select the file or folder whose changes you want to undo, right-click, and choose Undo Changes.

![](/media-occurrence/blog%3Acnblogs-19143256%3Amedia%3A13)

Choose what to undo. From top to bottom, the options are:

Undo one change while preserving later changes.

Undo a range of changes while preserving later changes.

Undo all changes from the selected point to the latest revision.

After selecting the changes, click Submit.

![](/media-occurrence/blog%3Acnblogs-19143256%3Amedia%3A14)

## Manually Editing Workspace Mappings

Only standard workspaces allow this; Stream workspace mappings cannot be edited.

![](/media-occurrence/blog%3Acnblogs-19143256%3Amedia%3A15)

Set the file mappings here directly; they can point to any depot.

For example, suppose your workspace is named Test.

You want files under UnrealPlugins in the Save depot to appear under the workspace's Plugins folder.

Write:

> //Save/UnrealPlugins/... //Test/Plugins/...

To exclude Prefixed under UnrealPlugins, add a leading -.

> \-//Save/UnrealPlugins/Prefixed/... //Test/Plugins/Prefixed/...
