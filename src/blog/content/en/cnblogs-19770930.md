# Managing Configuration File Exclusion During Packaging

## Introduction

When a UE project is packaged, all `.ini` configuration files under `Config` are included by default. Debug switches, profiling parameters, test-server addresses, development keys, and internal plugin configuration may not belong in a release package. Test and production environments may also need different configuration sets.

UE controls configuration-file packaging through the `[Staging]` section in `DefaultGame.ini`. Manual maintenance requires the correct `+AllowedConfigFiles` / `+DisallowedConfigFiles` format and the project-name prefix.

This article records rule reading, writing, and cache reloads. For selecting files and copying excluded configuration, see the [SimpleConfigExclude overview](/en/works/simple-config-exclude/).

## Staging Rules and Synchronization

### 2.1 UE's Staging Mechanism

UE controls inclusion and exclusion during packaging through the `[Staging]` section in `DefaultGame.ini`:

```ini
[Staging]
+AllowedConfigFiles=MyProject/Config/DefaultInput.ini
+DisallowedConfigFiles=MyProject/Config/DefaultDebug.ini
```

Configuration selections ultimately need to become inclusion and exclusion rules in this section.

### 2.2 Scanning and Rule Synchronization

```cpp
}
```

This reads the file directly and then parses AllowedConfigFiles and DisallowedConfigFiles, avoiding sole reliance on existing `GConfig` cache entries.

### 2.3 Applying Rules

```cpp
void USimpleConfigExcludeSettings::ApplyExcludeRules()
{
    // 移除旧的 [Staging] 区段
    // 根据当前规则列表重新生成
    // 写回 DefaultGame.ini
    // 重新加载配置以保持状态一致
    GConfig->UnloadFile(IniFilePath);
    GConfig->LoadFile(IniFilePath);
}
```

The example rewrites the `[Staging]` section after a state change, then unloads and reloads configuration so the cache matches the file contents.
