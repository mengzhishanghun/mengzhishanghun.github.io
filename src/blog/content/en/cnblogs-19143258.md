# How to Configure TypeMap

This operation requires a server administrator account.

Open CMD, enter p4 typemap, and press Enter.

The TypeMap settings file opens automatically.

Copy the following content into it.

## Addition: when teams retain Binaries
To let members without a compiler open the project, distribute editor binaries tied to an explicit source revision, engine version, platform and configuration. Do not track everything merely because its directory is named Binaries, or submit every machine's temporary build output.

`+w` keeps workspace files writable and can suit selected local build outputs. It does not mean checkout, locking or submission. Define who builds and updates DLLs and `.modules` for concurrent work. Writable files cannot fix engine/source/binary mismatches that prevent loading.

Changing typemap does not automatically update the types of already tracked files. Review them individually within an authorized changelist. Do not change the server typemap or bulk file types just to follow this article. Check ignore behavior using `p4 ignores -v` in your own test environment rather than treating a copied Git ignore file as verified P4 rules. Ignore rules also do not untrack existing files.

Example check: in a separate test workspace inspect a DLL and `.modules` file's actual filetype, writability after sync and opened records, then load the matched outputs in a clean project. This article did not connect to P4 or revalidate the existing typemap; it adds collaboration boundaries rather than server-operation results.
