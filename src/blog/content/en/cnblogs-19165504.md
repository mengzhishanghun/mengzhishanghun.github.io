# Seamless Map Travel

# How It Works
Seamless map travel differs from traditional level streaming. Streaming places sublevels in one map and switches maps by controlling their loading and unloading.
Seamless travel first switches to a simple map, loads the destination in the background, and then switches to that map once loading finishes.

# Settings
Set the intermediate loading map under Maps → Advanced → TransitionMap in Project Settings. If none is configured, a default empty map is created.
![](/media-occurrence/blog%3Acnblogs-19165504%3Amedia%3A1)
Also enable UseSeamlessTravel in GameMode.
![](/media-occurrence/blog%3Acnblogs-19165504%3Amedia%3A2)
Note that streaming may fail in PIE editor mode and display a warning. In that case, enable PIE streaming as directed by the warning.
![](/media-occurrence/blog%3Acnblogs-19165504%3Amedia%3A3)
# Code Implementation
This function is not exposed to Blueprints, so add your own wrapper function.
```C++
UFUNCTION(BlueprintCallable, meta=(WorldContext="WorldContextObject", CallableWithoutWorldContext))  
static void OpenMap(UObject* WorldContextObject, TSoftObjectPtr<UWorld> Map);
```

```C++
void UMyBlueprintFunctionLibrary::OpenMap(UObject* WorldContextObject, TSoftObjectPtr<UWorld> Map)
{
	if(const APlayerController* PlayerController = Cast<APlayerController>(UGameplayStatics::GetPlayerController(WorldContextObject, 0)))
	{
		PlayerController->GetWorld()->SeamlessTravel(FPackageName::ObjectPathToPackageName(Map.ToString()), true);	
	}
}
```

# Notes
When loading the transition map, all Actors in the starting map unload, but HUD, PlayerController, and related functionality remain. A loading UI can be implemented in the HUD.
While loading the transition map, none of its logic or Actors load, but WorldSubsystem loading and unloading execute normally.
I have not yet found a way to query how long this method will take.

To determine when the new map has finished loading, consult the called function's documentation; it specifies which functions to override.
