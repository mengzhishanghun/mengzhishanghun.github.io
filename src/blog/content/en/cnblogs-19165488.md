# Fixing Missing Context in UObject Blueprints

# The Problem

Normally, when you create a Blueprint derived from UObject, you find that it cannot obtain a PlayerController.

![](/media-occurrence/blog%3Acnblogs-19165488%3Amedia%3A1)

It also cannot create UI without reporting an error.

![](/media-occurrence/blog%3Acnblogs-19165488%3Amedia%3A2)

The cause is that the parent class does not override GetWorld, so the Blueprint compiler cannot obtain context and reports errors.

# Solution

Once you understand the cause, the fix is straightforward: override GetWorld in the parent class. There are a few points to note.

Add this in .h:
```C++
virtual UWorld* GetWorld() const override;
```

Add this in .cpp:

```C++
UWorld* UAIFlow::GetWorld() const  
{  
    if (IsTemplate() || !GetOuter())  
    {  
       return nullptr;  
    }  
  
    return GetOuter()->GetWorld();  
}
```

Note that you cannot simply return directly here; that does not solve the problem. It must be written this way.

Because I create the object in an Actor, GetOuter points directly to that Actor, allowing me to obtain GetWorld correctly. Adjust the return logic to your own situation.
