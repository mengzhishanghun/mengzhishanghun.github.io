## 项目介绍

这是一个围绕语音对话、人物感知与场景互动开发的 UE 数字人项目。不同版本围绕相近的需求展开，包括与用户交谈、根据语言执行特定行为、让视线跟随人物，以及根据人物进入、停留和移动等状态作出回应。

对话是项目的核心功能。用户语音先转换为文字，交给大模型生成回答文字，再合成语音，最后驱动数字人的口型与表情。大模型可以通过 Ollama 在本地运行，也可以使用云端服务，支持两种方案切换。语音识别、问答和语音合成可按需求组合，采用本地、云端或混合部署。

项目逐步形成了可供不同版本共用的角色基础、交互流程和功能模块。服务接口、触发条件、角色动画和场景反馈可以按需求调整，在已有功能上组合新的交互逻辑。

## 我负责的工作

我负责 AI 服务与 UE 数字人的集成，包括语音识别、大模型调用、语音合成、本地与云端切换，以及口型、表情、人物感知和场景效果的联调。同时搭建交互流程与功能模块的基础结构，处理模块执行、数据传递、角色状态和流程切换。

| 工作部分 | 主要内容 |
| --- | --- |
| 语音与大模型 | 接入识别、问答、合成服务，组织文字和音频的传递 |
| 本地与云端 | 通过 Ollama 接入本地大模型，对接远端服务并支持方案切换 |
| 角色表现 | 配合声音驱动口型和表情，接入眼部视线与角色动画 |
| 场景交互 | 提示词触发效果、灯光控制、角色动作及人体感知联动 |
| 共用基础 | 组织流程、功能模块、共享状态与配置，适配相似需求 |

## 功能实现

### 完整的语音对话流程

对话流程由语音识别、大模型问答、语音合成和角色表现组成。识别服务输出文字，大模型接收文字并返回回答文字，语音合成服务再将回答文字转换为语音。

| 环节 | 输入 | 输出 |
| --- | --- | --- |
| 语音识别 | 用户语音 | 识别文字 |
| 大模型问答 | 识别文字 | 回答文字 |
| 语音合成 | 回答文字 | 生成的语音 |
| 数字人表现 | 已生成的语音及对应动画数据 | 声音播放、口型与表情 |

我负责在 UE 中串联这些环节，将前一步的结果传给下一步。语音生成后，再驱动口型与表情，由数字人在场景中作出回应。

识别、模型和合成服务各自只负责对应任务。替换其中一项服务时，主要调整该环节的接口和数据处理，再将文字或音频结果交给后续模块，衔接角色表现。

### Ollama 本地大模型与云端服务切换

本地方案通过 Ollama 运行大模型，例如 DeepSeek。语音识别得到的文字交给本地模型处理，模型返回的回答文字再传给语音合成服务。项目也接入过 ChatGLM，不同模型的调用由相应问答模块处理。

云端方案通过网络接口调用远端大模型服务。我负责两种方案的接入与切换，让项目可以根据使用需要选择本地或云端服务。数字人的渲染、声音播放、动画和场景交互始终由 UE 端完成。

语音识别与语音合成也分别提供本地、云端接入方案。这两个环节可与本地或云端的大模型服务组合，形成纯本地、纯云端和混合三种部署方式。切换方案时，需要按对应服务的接口要求处理请求和返回数据，再接入后续流程。

### 语音识别与交互输入

本地语音识别接入 sherpa-ncnn，云端方案通过 AzSpeech 调用 Azure Speech。我负责将用户语音交给相应服务，再把识别文字送入后续对话处理。

识别结果进入交互流程后，可以继续用于大模型问答，并结合提示词和场景逻辑形成具体回应。语音接入与场景效果分别处理，场景中的角色和物体由后续功能模块控制。

### 特定提示词与场景效果

在对话处理中加入预设提示词检测。检测到相应内容后，由对应指令模块执行场景逻辑，让用户通过语言触发数字人的行为或改变场景状态。

项目中的相关指令包括开灯、关灯、开始跳舞和结束跳舞。通过这些指令，语音对话可以与灯光控制、角色动作等效果配合，数字人也能通过场景中的行为回应用户。

我将提示词检测、指令执行和角色表现分别接入流程。具体效果由相应的功能模块实现，可以与已有的灯光、动画和场景控制逻辑组合。

### 语音、口型、表情与角色动画

大模型返回回答文字后，先由语音合成服务生成语音。本地方案接入 ChatTTS、VITS，云端方案通过 AzSpeech 调用 Azure Speech。生成的语音交给数字人播放，并用于后续口型与表情驱动。

本地方案使用 Ynnk Voice Lip-sync 等音频驱动方案生成口型与表情；云端方案接收 Azure Speech 返回的 Viseme 等动画数据，再由 UE 应用到角色。我负责将声音播放与相应的口型、表情动画接入同一套回应流程。

角色还区分待机、思考和说话等表现状态，身体与面部动画分别控制。两者都有待机动画池，可通过配置选择具体动画，并设置播放偏移、开始延迟和结束延迟。

语音回应、预设动作和行为触发共用角色的动画播放接口，具体交互流程决定何时执行。

### 摄像头人物跟踪与视线跟随

通过摄像头获取人物位置，并据此更新数字人的注视目标。用户在交互区域内移动时，角色的视线随之调整，在对话中看向交流对象。

项目通过 Azure Kinect 读取人体骨骼位置，角色根据目标位置计算朝向，并通过面部控制调整眼部目标。我负责将人物位置数据接入 UE 和 Control Rig，让眼部朝向随目标位置更新。

人物的位置和动作也用于其他场景互动，例如根据用户动作控制电梯升降。人物感知和语音分别提供输入，再由具体交互流程安排角色与场景如何回应。

### 人物行为感知与自动触发

项目还需要根据人物行为作出回应。各类检测拆成独立模块，读取人物位置、移动和人数等信息，再与配置条件比较。满足条件时，选择相应的预设动画作为角色反馈。

| 检测或触发方式 | 实现内容 |
| --- | --- |
| 进入与离开 | 检测人物进入、离开时的变化，触发对应的预设动画 |
| 距离变化 | 根据人物距离及靠近、远离条件触发回应 |
| 驻足停留 | 结合位置变化范围和驻足时间判断停留行为 |
| 移动速度 | 检测移动速度以及加速、减速条件 |
| 人数变化 | 根据人数增加、减少及配置的人数范围触发回应 |
| 长时间无交互 | 记录未发生交互的时间，达到配置条件后触发预设行为 |
| 定时动画 | 按配置时间触发动画，并使用对应的动画候选池 |
| 定时灯光 | 通过定时逻辑控制场景灯光开关 |

各模块分别保存检测所需的状态：距离和速度检测保留前一次状态，驻足检测结合位置范围与停留时间，无交互检测则记录经过的时间。按需求选择模块、配置检测条件和动画反馈后，再将其接入角色流程。

提示词触发与人物行为触发共用角色表现和场景控制功能。前者根据对话内容触发，后者根据人物状态或定时条件触发，再由各自的配置和功能模块决定具体回应。

### 交互流程与功能模块复用

为适配相近需求，我将固定的线性逻辑拆成角色基础、流程控制与功能模块。C++ 提供初始化、启动、更新、停止和清理接口，蓝图实现具体的服务调用、行为检测和场景交互。

流程预设保存在配置资产中。角色加载指定流程时创建独立实例，并可选择是否立即启动。流程按名称加载、启动或停止功能模块，每帧更新正在运行的模块；模块完成后，通过回调返回成功或失败，供后续逻辑判断如何继续。

模块之间通过共享状态对象读写布尔值、字符串和对象引用。流程负责安排执行，模块负责各自功能，共享状态用于传递数据，角色负责声音和动画表现。新增相似交互时，可以组合已有模块，并补充对应的服务调用或场景行为。

切换流程时还需要清理输入绑定和实例。停止时移除流程绑定的按键监听；卸载时先清除角色对当前流程的引用，再调用清理逻辑，避免清理过程中重复触发卸载。流程通过模块的停止、完成回调和清理接口管理其执行状态。

## 技术组成与服务联调

下列方案来自项目不同版本，按具体需求接入和组合。

| 环节 | 本地接入方案 | 云端接入方案 |
| --- | --- | --- |
| 语音识别 | sherpa-ncnn | Azure Speech，通过 AzSpeech 接入 |
| 大模型对话 | 通过 Ollama 运行本地大模型，如 DeepSeek；项目也接入过 ChatGLM | 网络接口调用远端大模型服务 |
| 语音合成 | ChatTTS、VITS | Azure Speech，通过 AzSpeech 接入 |
| 口型与表情 | Ynnk Voice Lip-sync 等音频驱动方案 | UE 接收并应用 Azure Speech 的 Viseme 等动画数据 |
| 人体感知 | Azure Kinect 骨骼数据，结合 UE 与 Control Rig | 在 UE 侧接入与处理 |
| 数字人表现 | UE、MetaHuman 的角色渲染、声音播放与动画 | 角色仍由 UE 端呈现 |

UE 与后端通过 HTTP、UDP 等方式交换数据，后续也接入了使用 WebSocket 的问答后端。各服务的接入模块分别处理请求和返回结果，流程再将识别文字、模型回答、语音及动画数据交给下一环节。

本地服务使用 Miniconda 分别管理 Python 环境，并处理 PyTorch、CUDA 等依赖。我负责配置服务运行环境、接入接口，并与 UE 端联调各环节的数据传递及角色回应。
