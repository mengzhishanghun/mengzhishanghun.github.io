## 项目介绍

这个项目围绕人体动作、实时数据与机器人机构之间的映射展开。从 Kinect 或外部数据获得输入后，在 UE 中处理骨骼、姿态和目标位置，再根据机器人结构形成模型动作或关节值。

动捕重定向与实时通信、三轴 IK 属于同一个项目的不同部分。我的工作覆盖输入接入、中间骨架、机器人映射、UDP 数据交接、滤波和位置求解；部分能力目前仍处于软件原型与模型调整阶段。

## 我负责的功能

| 功能 | 主要处理内容 |
| --- | --- |
| 动捕输入 | Kinect 骨骼读取、缺失关节过滤、位置与角度滤波 |
| 中间骨架 | 将输入姿态写入统一参照模型，供后续映射使用 |
| 机器人重定向 | 结合骨段比例、关节原点、旋转轴和限制组织模型动作 |
| 实时通信 | UDP JSON 收发、最新帧交接、输入超时与恢复处理 |
| 运动求解 | 复用机构定义与 IK 能力，区分输入有效和求解有效状态 |

### 动捕到机器人模型

输入侧先读取 Kinect 骨骼，分别处理位置与欧拉角，再写入 PN3 中间模型。机器人侧结合 URDF 的关节定义与骨段比例，构造 IK 目标或使用直接角度映射，最后通过平滑和每帧角度变化限制更新 UE 组件。

将输入处理与机器人映射拆开，便于分别检查采集波动、骨架姿态和机构参数，避免同时排查整条动作链。

### 实时数据与三轴位置求解

UDP 工作线程保留最新解析帧，游戏 Tick 按数据代次读取更新。超时后按协议规则输出零值并重置滤波，恢复时使用新输入重新进入处理。

三轴原型复用已有机构能力，处理单位与坐标系转换，将目标位置转换为三个关节值。输入接收与 IK 求解分别表达状态，避免把“网络有数据”当作“当前关节结果可用”。

## 解决的难点

### 人体与机器人结构不同

人体与机器人在关节数量、旋转轴、骨段比例和活动范围上都有差异。直接复制动捕旋转，可能产生末端偏移、关节越界或动作扭曲。

我先整理相对稳定的中间骨架，再按机器人结构进行比例换算与关节映射。需要追踪目标位置的链路使用 IK，适合直接传递角度的部分保留轴角映射，使不同结构有对应的处理方式。

### 欧拉角边界与输出抖动

角度从 179 度变为 -179 度时，实际转动很小，直接相减却会形成接近一整圈的变化。我对跨越边界的角度差做展开，再参与后续滤波，并在输出阶段保留插值和平滑、每帧角速度限制。

这些处理用于整理数值连续性与输入波动，骨骼方向和模型比例仍由重定向配置负责。

### 网络接收与场景更新不同步

UDP 收包和游戏 Tick 各自推进。如果把每个收到的数据包都排成必须执行的动作，处理目标会偏离“跟随最新状态”的需求。

原型采用最新帧交接，并使用本地接收时间判断数据新鲜度。滤波还根据运动快慢调整，以平衡静止抖动与快速动作的跟随滞后。

### 收到有效输入不等于求解成功

目标可能满足输入格式要求，但机构无法得到有效的位置 IK 结果。因此接口分别表达 `input_valid` 与 `ik_valid`；输入有效而求解失败时，清空关节输出，并保留两种状态的区别，供上层处理。

## 实现结果与开发状态

现有实现覆盖 Kinect 输入、中间骨架和 UE 机器人组件的动作映射，实时链路也已有最新帧交接、超时恢复、自适应滤波和三关节位置求解的软件原型。

Kinect 到中间模型的特定姿态扭曲、真实机构 URDF、真实数据和设备表现仍需继续调整与测试。三轴原型处理目标位置，不包含通用末端姿态约束；协议归零也不等于物理机构安全回零。

UE 模型动作与协议输出不能直接代表实体执行器已完成通信、反馈和控制闭环。本项目保持开发中状态。
