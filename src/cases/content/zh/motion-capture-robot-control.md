## 项目介绍

这个项目将人体动作和实时数据映射到机器人模型。从 Kinect 或外部数据获取输入后，在 UE 中处理骨骼、姿态和目标位置，再根据机器人结构生成模型动作或关节值。

动捕重定向、实时通信和三轴 IK 是同一项目的不同模块。我负责输入接入、中间骨架、机器人映射、UDP 数据交接、滤波和位置求解；部分功能仍处于软件原型与模型调整阶段。

## 功能实现与技术难点

| 功能 | 主要处理内容 |
| --- | --- |
| 动捕输入 | Kinect 骨骼读取、缺失关节过滤、位置与角度滤波 |
| 中间骨架 | 将输入姿态写入统一参照模型，供后续映射使用 |
| 机器人重定向 | 结合骨段比例、关节原点、旋转轴和限制组织模型动作 |
| 实时通信 | UDP JSON 收发、最新帧交接、输入超时与恢复处理 |
| 运动求解 | 复用机构定义与 IK 能力，区分输入有效和求解有效状态 |

### 动捕到机器人模型

#### 负责的实现

先读取 Kinect 骨骼，分别处理位置和欧拉角，再写入 PN3 中间模型。机器人侧根据 URDF 关节定义和骨段比例，构造 IK 目标或直接映射角度，最后经过平滑和每帧角度变化限制，更新 UE 组件。

输入处理与机器人映射分开后，可以分别检查采集数据的波动、骨架姿态和机构参数，缩小动作异常的排查范围。

#### 难点与处理

人体与机器人的关节数量、旋转轴、骨段比例和活动范围不同。直接复制动捕旋转，可能造成末端偏移、关节越界或动作扭曲。

我先将输入转换到相对稳定的中间骨架，再根据机器人结构换算比例并映射关节。需要跟踪目标位置的部分使用 IK，适合直接传递角度的部分则保留轴角映射。

角度从 179 度变为 -179 度时，实际转动很小，直接相减却会得到接近一整圈的变化。我先展开跨越边界的角度差，再用于滤波；输出时继续做插值、平滑和每帧角速度限制。

这些处理用于保持数值连续、减小输入波动。骨骼方向和模型比例仍需通过重定向配置处理。

### 实时数据通信与更新

#### 负责的实现

UDP 工作线程保留最新解析帧，游戏 Tick 根据数据代次读取更新。输入超时后，按协议输出零值并重置滤波；新输入到达后恢复处理。

#### 难点与处理

UDP 收包与游戏 Tick 的更新节奏不同。如果将收到的每个数据包都排队执行，就难以满足跟随最新状态的需求。

原型只交接最新一帧，并根据本地接收时间判断数据是否过期。滤波也会随运动快慢调整，兼顾静止时的抖动和快速动作的跟随滞后。

### 三轴位置求解与有效性判断

#### 负责的实现

三轴原型复用已有机构定义和求解功能，完成单位与坐标系转换，再根据目标位置计算三个关节值。输入接收和 IK 求解分别报告状态，区分“已收到有效输入”和“已得到可用的关节结果”。

#### 难点与处理

输入格式正确，不代表机构一定能求出有效的位置 IK 结果。接口因此用 `input_valid` 和 `ik_valid` 分别表示输入与求解状态。输入有效但求解失败时，清空关节输出，并保留这两个状态供上层判断。
