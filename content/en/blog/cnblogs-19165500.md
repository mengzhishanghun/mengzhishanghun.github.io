# Custom Configuration with DeveloperSettings

# Creation
![](/media-occurrence/blog%3Acnblogs-19165500%3Amedia%3A1)
Create a class derived from UDeveloperSettings.
In the class attributes, Config=Game means configuration in Game.ini; adding DefaultConfig changes this to DefaultGame.ini.
The value after config= is the configuration filename.
Thus this example uses DefaultVehicle.ini.



# INI Configuration Format
![](/media-occurrence/blog%3Acnblogs-19165500%3Amedia%3A2)
The configuration format is [/script/module name/class name].
![](/media-occurrence/blog%3Acnblogs-19165500%3Amedia%3A3)
Map format is ((key,value),(key,value)).
Maps and Arrays can both continue on subsequent lines with +; they need not all be written on one line.

# Editor Project Settings
![](/media-occurrence/blog%3Acnblogs-19165500%3Amedia%3A4)
The value after DisplayName= is the name shown in the editor's Project Settings.

The category depends on the value after config=.
It can be game, engine, or plugins.
You can also use a custom value; custom ones are placed under engine by default.

Once DefaultConfig is added, changing values here generates the configuration file automatically.

# Access
![](/media-occurrence/blog%3Acnblogs-19165500%3Amedia%3A5)
In C++, obtain it through GetDefault.
![](/media-occurrence/blog%3Acnblogs-19165500%3Amedia%3A6)
In Blueprints, obtain it through GetClassDefaults.
# Packaging Exclusion
![](/media-occurrence/blog%3Acnblogs-19165500%3Amedia%3A7)
First add the configuration file to exclude in DefaultGame.ini.
![](/media-occurrence/blog%3Acnblogs-19165500%3Amedia%3A8)
Then add the reference declaration to the corresponding module, so packaging copies the file into the packaged config directory automatically.
The benefit is that game rules can still be changed by editing the configuration file after packaging.
