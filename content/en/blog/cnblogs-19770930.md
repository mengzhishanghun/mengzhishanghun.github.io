# Managing Configuration File Exclusion During Packaging

## Introduction

When a UE project is packaged, all `.ini` configuration files under `Config` are included by default. In practice, you may not want some configurations in the release:

-   **Debug configuration**: development debug switches and profiling parameters
-   **Development environment configuration**: test-server addresses and development keys
-   **Private plugin configuration**: internal settings of certain plugins that do not need to ship
-   **Multiple deployment environments**: test and production environments require different configuration sets

UE provides the `[Staging]` section in `DefaultGame.ini` to control configuration-file packaging. However, editing it manually is tedious and error-prone: you must remember the correct format (`+AllowedConfigFiles` / `+DisallowedConfigFiles`) and include the project-name prefix.

## Staging Rules and Synchronization

### 2.1 UE's Staging Mechanism

UE controls inclusion and exclusion during packaging through the `[Staging]` section in `DefaultGame.ini`:

```ini
[Staging]
+AllowedConfigFiles=MyProject/Config/DefaultInput.ini
+DisallowedConfigFiles=MyProject/Config/DefaultDebug.ini
```

A visual management tool can convert configuration selections into inclusion and exclusion rules in this section.

### 2.2 Scanning and Rule Synchronization


This reads the file directly and then parses AllowedConfigFiles and DisallowedConfigFiles, avoiding sole reliance on existing `GConfig` cache entries.

### 2.3 Applying Rules

```cpp
void USimpleConfigExcludeSettings::ApplyExcludeRules()
{
    // 移除旧的 [Staging] 区段
    // 根据当前规则列表重新生成
    // 写回 DefaultGame.ini
    // 重新加载配置以保持状态一致
    GConfig->UnloadFile(IniFilePath);
    GConfig->LoadFile(IniFilePath);
}
```

The original example rewrites the `[Staging]` section after a state change, then reloads the configuration.
