# Calling a DLL

Here is my approach. I am not sure whether it is entirely correct, but it works, haha. I followed the official third-party library example.
![](/media-occurrence/blog%3Acnblogs-19174295%3Amedia%3A1)
I will skip the DLL packaging process and focus on what to do once you have the DLL and Lib.
Take TestThird, a plugin created from the official template, as an example.
Place the dll and lib files in `TestThird\Source\ThirdParty\TestThirdLibrary\x64\Release
Then place a dll in `TestThird\Binaries\ThirdParty\TestThirdLibrary\Win64`.
In theory this step could be improved with automatic copying, but I have not had time to look into it.
After adding the files, add the following to the module's Build.cs:
![](/media-occurrence/blog%3Acnblogs-19174295%3Amedia%3A2)
Finally, add an .h file with the same name as the dll to the module to declare the functions you can call in the dll.
![](/media-occurrence/blog%3Acnblogs-19174295%3Amedia%3A3)
If you do not know which functions the DLL contains, download [Dependencies](https://github.com/lucasg/Dependencies).
![](/media-occurrence/blog%3Acnblogs-19174295%3Amedia%3A4)

Drag the DLL into it to inspect the functions. Very convenient.
Finally, call FPlatformProcess::GetDllHandle when the module loads. I modified my version slightly; it is roughly like this.
Do not copy this directly: I changed it temporarily for illustration. In practice, it should receive windll, macdll, and linuxdll.
![](/media-occurrence/blog%3Acnblogs-19174295%3Amedia%3A5)
Remember to call FPlatformProcess::FreeDllHandle when the module unloads.
![](/media-occurrence/blog%3Acnblogs-19174295%3Amedia%3A6)
You can now call it conveniently: include the header and call the functions normally.
![](/media-occurrence/blog%3Acnblogs-19174295%3Amedia%3A7)
