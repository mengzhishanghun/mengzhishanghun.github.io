# Implementing SSH Tunnels in UE for Secure Access to Remote Services

## Introduction

UE projects often need access to databases, APIs, or internal services on remote servers. Exposing these services directly to the public internet carries security risks. An SSH Tunnel offers a secure solution: forwarding a local port to a remote service through an encrypted SSH channel, protecting data in transit while avoiding direct service exposure.

This article explains how SSH tunnels work and how to implement them in UE.

* * *

## Ways to Implement SSH Tunnels

### Calling the System SSH Client

Let's start with the simplest approach: using the system's SSH client.

**Windows (using the OpenSSH client):**

```cpp
#include "GenericPlatform/GenericPlatformProcess.h"

void CreateSSHTunnelByCommand(
    const FString& SSHHost,
    int32 SSHPort,
    const FString& Username,
    const FString& Password,
    int32 LocalPort,
    const FString& RemoteHost,
    int32 RemotePort)
{
    // 构建SSH命令
    // ssh -L LocalPort:RemoteHost:RemotePort Username@SSHHost -p SSHPort
    FString Command = FString::Printf(TEXT("ssh -L %d:%s:%d %s@%s -p %d -N"),
        LocalPort, *RemoteHost, RemotePort,
        *Username, *SSHHost, SSHPort);

    // 使用UE的进程管理启动SSH
    FProcHandle ProcHandle = FPlatformProcess::CreateProc(
        TEXT("C:/Windows/System32/OpenSSH/ssh.exe"),
        *Command,
        true,   // bLaunchDetached
        false,  // bLaunchHidden
        false,  // bLaunchReallyHidden
        nullptr,
        0,
        nullptr,
        nullptr
    );

    // 保存进程句柄用于后续关闭
    if (ProcHandle.IsValid())
    {
        UE_LOG(LogTemp, Log, TEXT("SSH隧道已启动"));
    }
}

// 关闭SSH隧道
void CloseSSHTunnel(FProcHandle& ProcHandle)
{
    if (ProcHandle.IsValid())
    {
        FPlatformProcess::TerminateProc(ProcHandle);
        FPlatformProcess::CloseProc(ProcHandle);
    }
}
```

**Advantages and disadvantages:**

✅ **Advantages:**

-   Simple implementation in just a few lines
-   No third-party library integration required
-   Uses the system SSH client

❌ **Disadvantages:**

-   Depends on the system environment (an SSH client must be installed)
-   Cannot supply passwords in code (requires keys or manual entry)
-   Complex process management and difficult connection-state retrieval
-   Poor cross-platform compatibility (different Windows/Linux/Mac paths)
-   Cannot obtain detailed error information
-   Unsuitable for packaged distribution (user environments are outside your control)

* * *

### Integrating an SSH Library

A more reliable approach is to integrate a dedicated SSH library.

Here I use the open-source combination of libssh2 + OpenSSL, requiring two key libraries:

**libssh2**—SSH protocol implementation

-   Establishes SSH connections
-   User authentication (password/keys)
-   Port forwarding
-   🔗 Open-source repository: [https://github.com/libssh2/libssh2](https://github.com/libssh2/libssh2)
-   📄 License: BSD 3-Clause

**OpenSSL**—cryptographic support

-   Provides underlying cryptographic algorithms
-   Key exchange
-   Data encryption/decryption
-   🔗 Open-source repository: [https://github.com/openssl/openssl](https://github.com/openssl/openssl)
-   📄 License: Apache 2.0

### Using These Two Libraries

Basic steps to integrate libssh2 into a UE project:

**1\. Compile the libraries**

First compile static libraries for libssh2 and OpenSSL for the target platform:

```bash
# Windows平台需要编译出
libssh2.lib / libssh2.dll
libcrypto.lib / libcrypto.dll
libssl.lib / libssl.dll
```

**2\. Add dependencies in .Build.cs**

```csharp
// 添加头文件路径
PublicIncludePaths.Add(Path.Combine(ThirdPartyPath, "libssh2", "include"));
PublicIncludePaths.Add(Path.Combine(ThirdPartyPath, "openssl", "include"));

// 链接静态库
PublicAdditionalLibraries.Add(Path.Combine(ThirdPartyPath, "libssh2", "lib", "libssh2.lib"));
PublicAdditionalLibraries.Add(Path.Combine(ThirdPartyPath, "openssl", "lib", "libcrypto.lib"));
PublicAdditionalLibraries.Add(Path.Combine(ThirdPartyPath, "openssl", "lib", "libssl.lib"));

// 运行时需要的DLL
RuntimeDependencies.Add("$(BinaryOutputDir)/libssh2.dll", Path.Combine(ThirdPartyPath, "libssh2", "bin", "libssh2.dll"));
```

**3\. Basic libssh2 workflow**

```cpp
#include "libssh2.h"

// 初始化libssh2
libssh2_init(0);

// 创建会话
LIBSSH2_SESSION* session = libssh2_session_init();

// 连接到SSH服务器（基于已有的Socket）
libssh2_session_handshake(session, socket);

// 用户认证
libssh2_userauth_password(session, username, password);

// 创建端口转发通道
LIBSSH2_CHANNEL* channel = libssh2_channel_direct_tcpip(
    session,
    remote_host,  // 远程目标地址
    remote_port   // 远程目标端口
);

// 后续进行数据转发...

// 清理资源
libssh2_channel_free(channel);
libssh2_session_disconnect(session, "Normal Shutdown");
libssh2_session_free(session);
libssh2_exit();
```

**Key points:**

-   libssh2 requires a Socket; you can use `FSocket` in UE
-   Port forwarding needs a local listening Socket to accept connections
-   Data forwarding must run in a loop on a separate thread to avoid blocking the main thread
-   All libssh2 operations need proper error handling and resource cleanup

### Comparing the Two Approaches

| Feature | System SSH | Integrated SSH library |
| --- | --- | --- |
| **Implementation difficulty** | Simple | Complex |
| **Environment dependency** | Requires a system SSH client | None |
| **Password authentication** | Unsupported (manual entry required) | Fully supported |
| **State monitoring** | Difficult | Fully supported |
| **Error handling** | Details unavailable | Detailed errors |
| **Cross-platform** | Inconsistent paths | Unified interface |
| **Packaged distribution** | Unreliable | Reliable |
| **Use cases** | Development and testing | Production |

**Conclusion:**

-   For temporary testing, calling system SSH is the fastest approach
-   For a production-grade feature, integrating an SSH library is the only choice
