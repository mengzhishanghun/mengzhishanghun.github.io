使用文档

SimpleBPInheritFix 使用文档

SimpleBPInheritFix 的完整中文产品使用文档

支持的虚幻引擎版本：5.2–5.8

一键修复 Actor 蓝图继承链组件污染 Bug。

⚠️ 此插件会修改继承链上的多个蓝图。修改是保守的，但在提交到版本控制前，请确认自动签出的文件是否符合预期。

📝 使用方法

Section titled “📝 使用方法”
  1. 安装插件并编译成功
  2. 在内容浏览器中，右键任何受影响的 Actor 蓝图（祖先/自身/后代均可）
  3. 选择 Component Repair → Fix Inheritance Pollution
  4. 打开输出日志并过滤 LogSBIF 以监控执行
  5. 编辑器会弹出保存对话框——保存标记为脏的蓝图即可完成

❓ 常见问题

Section titled “❓ 常见问题”

扫描返回 0 个发现但明显存在损坏？
你遇到的可能不是此插件覆盖的问题（罕见情况）。请粘贴完整的 LogSBIF 日志以供诊断。

CheckOut 失败怎么办？
插件会继续进行内存中的修复，但你需要在保存前手动处理签出（p4 edit / git lfs lock / svn lock）。常见原因：文件被他人锁定、服务器不可达、或映射未包含该文件。

应该选择哪个蓝图作为锚点？
随意选择——祖先、自身和后代都会被扫描，结果相同。

没有 Perforce 也能用吗？

  • Git：CheckOut 本质上是空操作，文件默认可写
  • Git LFS：发起 LFS lock 请求
  • SVN：运行 svn lock
  • 无版本控制：跳过 CheckOut 阶段

⚠️ 限制

Section titled “⚠️ 限制”
  • 仅处理此插件覆盖的特定组件污染问题；其他蓝图问题不在范围内
  • 不扫描在 Construction Script 中动态创建的组件

SimpleBPInheritFix 使用指南

Section titled “SimpleBPInheritFix 使用指南”

SimpleBPInheritFix 用于处理 Actor 蓝图继承链中特定的组件状态异常。

操作步骤

Section titled “操作步骤”
  1. 安装插件，编译通过
  2. Content Browser 里右键任意受影响的 Actor 蓝图

  4. 打开 Output Log，过滤 LogSBIF，查看执行情况
  5. 编辑器弹出保存对话框，保存被标脏的蓝图 即完成

常见问题

Section titled “常见问题”

扫描结果 0 条但确有污染？

Section titled “扫描结果 0 条但确有污染？”

扫描结果为 0 时，需要结合 LogSBIF 日志判断是否属于此工具处理的组件状态异常。

CheckOut 失败怎么办？

Section titled “CheckOut 失败怎么办？”

插件仍会完成内存修复，但保存前需要手动处理签出。常见原因：

  • 文件被他人锁定
  • 源控制服务器不通
  • Workspace mapping 不包含该文件

先手动解决签出，再回 UE 保存。

会不会把正常组件改坏？

Section titled “会不会把正常组件改坏？”

工具的修复范围是：只翻转 CreationMethod 这一个字段（Instance → SimpleConstructionScript），其他任何属性都不动。保存前仍需检查受影响蓝图的组件状态。

锚点蓝图选错会有影响吗？

Section titled “锚点蓝图选错会有影响吗？”

入口蓝图用于定位继承链；扫描会覆盖祖先、当前蓝图与后代。

非 Perforce 能用吗？

Section titled “非 Perforce 能用吗？”
  • Git：签出基本是空操作，文件本就可写
  • Git LFS：会自动请求 LFS lock
  • SVN：执行 svn lock
  • 无源码控制：签出阶段整个跳过，直接进入修复

使用范围

Section titled “使用范围”
  • 只处理本插件覆盖的那种组件异常（CreationMethod=Instance 污染），其他类型的蓝图问题不在范围内
  • Construction Script 里动态生成的组件不在扫描范围（那些本就不走 SCS/ICH）
  • 仅支持 Actor 蓝图（非 Actor 的蓝图不存在此问题）
