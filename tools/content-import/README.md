# 网站内容局部同步

本站当前只有静态发布树。此工具从 MyObsidian 的 `网站/` 读取固定清单，更新本轮允许同步的内容，并在写入前检查来源和页面结构。它不扫描笔记库寻找新文章。

## 运行

在本目录执行：

```powershell
npm ci
node import.mjs --vault "MyObsidian 的本机路径"
node import.mjs --vault "MyObsidian 的本机路径" --check
npm run test:rejection -- --vault "MyObsidian 的本机路径"
```

`--check` 只读验证；若网站与来源不一致，退出码为 1。导入器先生成完整的变更和临时 Pagefind 索引，再更新发布树。连续运行两次后，第二次应显示静态文件待更新 0、待删除 0，并以退出码 0 结束。
`test:rejection` 只复制清单内来源到系统临时目录，验证未知图片、原始 HTML 和事件属性会被拒绝，且失败后发布树字节不变。

## 固定边界

- `manifest.json` 明确列出 36 篇已公开笔记、7 个案例、16 份手册、24 篇现有作品详情，以及要删除的旧路由。部分历史笔记与作品仍为 `sitePublish: false`，清单只承认现有路由；新增来源不会自动发布。
- 笔记只同步标题、说明、相关列表卡片、上下篇和 RSS 标题。现有正文、代码块、图片与视频包装原样保留。清单记录除首个标题外的正文摘要；正文变化会在写入前失败，必须另行处理媒体与完整渲染。
- 笔记标题区位于阅读详情内、正文之前；导入器兼容旧版布局并将其更新为单列标题区。Pagefind 以包含标题和正文的阅读详情为索引根节点，忽略面包屑、目录和上下篇导航。
- 手册只同步联系章节和已核对的主文章标题层级；现有代码、表格、媒体和补充指南正文保留。清单记录主文其他部分及补充正文的摘要。
- 当前实际文档页固定深色主题，并与笔记、作品详情共用阅读区样式；导入器只更新这些实际页面，跳转页保持原样。
- 案例正文按来源的“主要说明、环境、出现的问题、解决方案、结果”五节生成。找不到已有公开资源时停止，不复制笔记库附件。
- 作品正文以 OB 的 `网站/作品/` 中固定来源为准，只替换对应详情页的正文和目录内部。页面标题区、摘要、按钮、封面、脚本和其他外壳保留现状。作品必须按“作品简介、背景与目标、核心能力、适用场景、适用范围与边界”排列 H2，可在末尾增加“效果展示”；核心能力使用 H3。正文变化会同步，frontmatter 属性漂移则拒绝。
- 唯一登记的作品图片是 UEPackageManager 的本地截图。清单冻结图片源文件 hash 和现有隐藏占位节点 hash；导入器在 Markdown AST 中识别普通、尖括号及引用式图片，只保留已登记图片对应的隐藏占位，不复制图片或恢复公开。未知图片、源文件变化或占位变化会在写入前拒绝。
- 不支持同步的 frontmatter 字段以清单中的历史值为门禁，普通运行不会刷新基线。来源结构、slug、发布标记或页面边界不符时停止。
- 所有笔记索引由实际公开 HTML 的 `[data-blog-article]` 区域重新生成。静态路由 `/blog/` 保持不变。

更新清单中的路由、属性基线或媒体许可属于扩大内容范围，需先确认允许公开的来源和资源。作品正文更新不需要刷新来源快照 hash；`sourceBaselineSha256` 只记录接入时版本，实际同步以当前正文和冻结属性门禁为准。
